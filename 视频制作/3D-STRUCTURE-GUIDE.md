## 0. 一句话

**代码层内部再分两档：2D 档管逻辑与数据，3D 档（Three.js）管空间结构与机械联动；H3 只负责「像真的」实拍质感。** 三档各有边界，不互相替代。

## 1. Q2 分档：什么时候需要代码-3D

Q2 判定「画面是否表达原理/结构/因果」；命中后再按表达需求分档：

| 画面内容 | 归属 | 理由 |
| --- | --- | --- |
| 数据图表、曲线、公式、流程步骤 | 代码-2D | 数值/逻辑即输入，精确可复现 |
| 电路逻辑、电流路径、状态流程 | 代码-2D | 符号与方向必须一字不差 |
| **设备内部结构**：电机转子/定子、逆变器桥臂、电池包布局、机械传动 | **代码-3D（形态 D）** | 观众要理解「部件在内部哪里、长什么样、怎么连」；H3 无正确性保障、2D 图标给不了空间感 |
| 3D 剖视中的电路/逻辑细节 | 代码-2D 画中画 inset | 3D 管空间定位，2D 管逻辑细节，组合而非替代 |
| 标题卡、章节卡、HUD、字幕 | 代码（2D） | 全片统一规范 |
| 真实质感（道路/车内/材质/人物动作） | H3 | 实拍感由生成模型承担 |

> ⚠️ **典型成因**：原理段只有 2D 图标链、缺 3D 空间结构层 → 「逻辑对但没画面感」。涉及机械/电气结构的主题，分镜阶段**至少安排 1 个 3D 剖视镜头**。

## 2. 形态 D：代码-3D 结构镜头

- **职责**：Three.js 剖视/拆解、部件联动、能量流粒子、相机运镜；仍属代码层，**确定性渲染、纯 CPU、不占 GPU 窗口**，H3 不参与。
- **技术栈**：Remotion + `three` + `@react-three/fiber` + `@react-three/drei`。3D 场景就是 React 组件，帧号驱动动画，与 2D 镜头、字幕**共用同一条唯一时间轴**。
- **资产来源**：优先免版权 GLB（Sketchfab 等 CC 授权，登记 MANIFEST 来源 URL/许可）；无合适模型用几何体搭简化结构（盒体车身 + 圆柱车轮 + 部件块），风格与原片统一。**简化不是缺点：科普剖视要的是关系正确，不是照片级细节。**
- **真实感**：靠材质、环境光、接触阴影在代码内解决，不依赖 H3。

## 3. 五条硬规则（违反即返工）

1. **单一状态机**：所有运动方向（转子转向、能量流方向、部件联动、高亮归属）由唯一状态机（如 `drive | regen`）派生；禁止各组件各写方向常量——方向正确性是 3D 档存在的理由。
2. **布局以调研文档为准**：电机在轴端、逆变器紧邻电机、电池包铺底盘；不指向未核实的具体车型。
3. **3D 场景内零文字**：部件标签、数值一律走代码叠加层（同形态 C 规则）；数字必须在叠加层/字幕再画一遍。
4. **props 可调**：相机参数、剖切透明度、粒子速度暴露成 props，在 Remotion Studio 预览里实时调，不用自然语言来回描述机位。
5. **字幕安全区**：底部字幕带内不放 3D 内容/标注；入场动画轨迹不穿过字幕带。

## 4. 与 2D inset 的组合原则

- 3D 管「在哪、长什么样、怎么连」；2D 管「电路/逻辑细节」。
- 标准做法：3D 剖视推进到某部件时，在安全区（右上等）以**画中画**嵌入 2D 原理图 inset（直接复用已有 2D 组件），空间与逻辑一次讲清。
- inset 与 3D 图层同属一个镜头条目，统一调时长；inset 动画由代码逐帧定义，不依赖 3D 画面内元素跟踪。

## 5. 与 H3 的边界

- **3D 结构镜头默认不交给 H3 动效化**：把 3D 剖视帧当首帧喂 H3 虽可行，但结构保持风险高、收益低。
- H3 继续只做外观实拍感镜头；3D 镜头不占 GPU 窗口。
- **H3 明确不做**：字幕、数据数字、原理示意、内部结构剖视、章节结构、配音解说、最终拼接——即使「能画」也不允许。
- 若 H3 镜首帧由代码渲染（含 3D 帧），关键数字仍需在叠加层/字幕由代码再画一遍，H3 保持失败也不影响事实正确。

## 6. 质检

| 检查项 | 执行方 |
| --- | --- |
| 空帧/长时间静止、字幕越界、响度、时长一致 | 代码层脚本自动 |
| 画面数字与调研文档逐一比对 | 代码层脚本 + 人抽查 |
| **3D 转向/能量流方向与状态机一致、部件布局与调研文档一致** | **代码断言自动校验 + 人目检空间关系** |
| 3D 帧内零文字（标签是否只存在于叠加层） | 抽帧 + 空文字层断言 |
| 镜头衔接（前段离场 → 后段首帧入场）、风格统一 | 代码层规则 + 人看样片 |

## 7. 返工路径（改什么，动哪层）

| 修改需求 | 动哪层 | 成本 |
| --- | --- | --- |
| 改数字/标注位置/镜头顺序时长 | 只动代码，重渲对应段 | 低，CPU |
| 3D 结构/运镜/节奏不满意 | 改 Three.js 场景参数或 props，CPU 重渲该段 | 低–中，不占 GPU 窗口 |
| 原理段「逻辑对但没空间感」 | 补形态 D 镜头替换 2D 图标链，2D 逻辑图降级为 inset | 中，纯代码层 |
| H3 运动/氛围不满意 | 改提示词或关键帧 → 重进 GPU 窗口 | 中，占窗口时间 |
| H3 构图/配色不满意 | 改代码关键帧 → 重进窗口 | 中 |
| 改解说词一个字 | 文稿重定稿 → TTS 重生成 → 全片帧号重排 | 高（最贵返工，文稿定稿是最重要的人工确认点） |
