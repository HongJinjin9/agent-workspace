# ComfyUI H3 视频版（优云智算 · RTX 5090）实测与接入

> 状态：实测记录 + 接入方案，待评审。
> 实测时间：2026-11-12 13:01–14:01（按小时计费的 1 小时窗口）。
> 应用：`ComfyUI H3 视频版` ｜ RTX 5090 ×1（32 GB 显存）｜ 约 **¥2.84/小时**。
> 仓库惯例是「成片、静帧不入库」：本目录只保留文档、脚本与一个可直接提交的 API 工作流，测试片按 §七 可重新生成。

## 一、结论

| 问题 | 结论 |
| --- | --- |
| 能否登录 | **能**。门禁是自研 `WyfGate`（不是 JupyterHub），账号密码换 `wyfgate` cookie，7 天有效；HTTP API 与浏览器同一套 |
| 能否操作 ComfyUI | **能**。ComfyUI 0.36.0 + 2394 个节点；HTTP API 可读写 stats / object_info / models，提交 `/prompt`、下载 `/view` |
| 单卡能不能跑 MiniMax H3 | **能，而且是刚好**。int8 量化 + 8 步加速 LoRA，5 秒 768p 实测显存 **31 GB / 32 GB**；24 GB 卡跑不动这套配置 |
| 出片速度 | 864×480 / 5 s / 8 步：**108 秒冷启 / 61.5 秒热**；1280×736：220 秒；9:16 竖屏 100 秒；首尾帧双控 71 秒 |
| 产物规格 | 480×864 / 864×480 / 1280×736，24fps，H.264 + **AAC 立体声音轨**——H3 一次前向同时出画面与环境声/音效 |
| 对视频制作的价值 | **补「实拍质感」镜头**：Pexels 找不到、程序化做不出的减速带/积水倒影/雨滴等，1–4 分钟一条 |
| 主要限制 | 开放权重上限约 768p（可用帧级超分补到 1080p）；单次 5–15 秒（可用尾帧续接）；文字/车牌会乱码；**商用需 MiniMax 商业许可**（见 §六） |

一句话：**补画面质感有效，替代不了数据动效与整条时间轴**。推荐「生成 768p → 超分/本机放大调色 → 进现有 timeline」。

## 二、怎么连（门禁 + 客户端）

门禁是应用自带的登录层，不是 ComfyUI 自带登录：

```
GET  /            → 401 {"error":"unauthorized",...}       （服务端 WyfGate/1）
POST /login  u=…&p=…  → 302 + Set-Cookie: wyfgate=<token>; HttpOnly; Secure; Max-Age=604800
带上 cookie 后 → 200  ComfyUI 前端
```

- 凭据只走环境变量 `H3_USER` / `H3_PASS`，**不写进仓库**；应用按小时租用，到期即失效。
- 应用没开机时门禁仍在线（返回 401/502，业务路径空 body），`comfy_client.py` 会直接报 `APP DOWN`，不是账号问题。
- 客户端 `tools/comfy_client.py`（依赖 `requests`）：

```bash
export H3_USER=... H3_PASS=...
python3 tools/comfy_client.py stats                 # 显卡 / 版本 / 内存
python3 tools/comfy_client.py nodes --grep H3       # 节点清单
python3 tools/comfy_client.py models                # 模型目录
python3 tools/comfy_client.py run workflows/t2v_api.json --out out/
```

> `/prompt` 只认「导出 (API)」的**扁平节点** JSON，不认 UI 模板的 subgraph 结构。`workflows/t2v_api.json` 是实测用的 23 节点 API 版（UI 模板先加载再 `graphToPrompt()` 展开即可）。改提示词/分辨率/时长看 `140:131`（prompt、width/height）与 `140:133`（时长，秒；帧数由 `140:132` 表达式算出）。

应用预置 27 个中文工作流（文生视频/图生视频/首尾帧/长视频接续/2K 放大/ControlNet 等），在 UI 左侧 **Workflows** 面板搜索加载；官方模板库另有 22 个 H3 相关模板。官方模板也是 subgraph，API 提交前必须展开。

| T10 | **768p→1080p 超分** | 1920×1080 | 5 s | — | **107.5 s** | ¥0.085 | 4x-UltraSharp + lanczos |
| T11 | **长视频接续**（尾帧→首帧） | 864×480 | 5 s | 8 | **125.5 s** | ¥0.099 | 接缝 MAE 2.5/255、corr 0.998 |

**规律**：耗时 ≈ 像素数 × 帧数 × 步数 × 常数；首次调用额外 30–40 s 加载模型，同进程连续调用明显更快。批量生产把同分辨率/同时长的镜头排在一起。FastH3 与「普通 H3 + 8 步 turbo LoRA」速度几乎一样，选一条固定用。

**能力边界**：H3 对**动作/机位**服从好，对**光线/时间/文字**服从差——想要的影调靠首帧图锁（I2V 比 T2V 稳），文字与数字留给程序化，车牌类近景要遮。

## 四、对 `agent-workspace` 视频制作的具体用法

`自媒体稿/第04期-你的身体比参数表更懂车.md` §6.2 的缺口，逐条对应：

| 稿件缺口 | 原方案 | 怎么补 |
| --- | --- | --- |
| 减速带/颠簸路面实拍 | Pexels 补 B-roll | 文生视频：慢速过坎 + 车身起伏（S2「咚 / 咣当」两版对照） |
| 积水倒影 | Pexels 补雨夜积水 | **已实测**：车尾灯倒影荡开又收敛，可作 S2 曲线的物理载体 |
| 弯道侧倾/后视镜 | Pexels / 现有车内素材加倾斜 | 图生视频：抽现有素材一帧当首帧，加「车身向外倾、地平线转动」 |
| 雨滴打在挡风玻璃 | 复用 `rain_window` | **已实测**：加速瞬间雨滴被拉成斜线，jerk 的可见证据 |
| 三条曲线动效 | 程序化（PIL/numpy） | 仍走程序化——曲线要跟数学函数严格对应，生成模型做不准 |

**分工原则**：实拍质感镜头交给生成，数据/文字/精确图形留给程序化。提示词模板见 [`prompts.md`](./prompts.md)（S1–S5 分镜与负向清单，英文出片更稳；写法为「镜头语言 + 物理后果 + 声音」）。

**推荐生产流程**（与现有管线拼接，不推翻）：

```
分镜（shots.json）→ 挑「需要实拍质感」的镜头 → ComfyUI 生成 5 s 素材（768p）
  → 下载 → 本机超分/ffmpeg：放大到 1080p、统一调色颗粒遮幅、与旁白对齐
  → 进现有 timeline.json → finalize.py 出片
```

- **分辨率**：开放权重上限约 768p，2K 要走 latent 放大；1080p 交付用 T10 的帧级超分链路（脚本 `tools/upscale_video.py`）。
- **时长**：单条 5–15 s；更长按 5 秒切段、用尾帧接首帧，拼接时裁掉重叠 1–2 帧；一条只做一个动作。
- **音频**：H3 自带音轨可当音效/环境声素材；旁白仍走 edge-tts。
- **一致性**：同场景多条用同一 seed + 同一提示词前缀，镜头间靠首帧/尾帧衔接。
- **成本**：单条 5 s / 864×480 约 ¥0.085；一条 3 分钟片子的 10 个生成镜头约 20–40 分钟机器时间 ≈ ¥1–2。真正的成本是「选哪个镜头值得生成」的判断。

## 五、踩过的坑

| 现象 | 原因 / 处理 |
| --- | --- |
| 门禁能登录、所有页面 502、body 为空 | 应用没开机。门禁常驻，应用按时计费；客户端会报 `APP DOWN` |
| UI 模板能跑，API 提交报错 | 模板用 subgraph，`/prompt` 只认展开后的扁平节点 |
| 首帧 16:9，出来却是正方形 | `ResolutionSelector` 的 `aspect_ratio` 覆盖首帧比例；I2V 时设成首帧同比例 |
| 视频里的车牌/招牌乱码 | H3 对文字渲染不可控；避开带文字近景或后期遮挡 |
| 显存只剩 0.3 GB | 实测能稳定跑完 5 秒 768p；不要并发第二个任务，采样时别用浏览器重跑 |

## 六、风险与合规（必须看）

1. **商业许可**：MiniMax H3 是开放权重，但本地权重的**商用输出需通过 Comfy 购买商业许可**。本系列有广告分成/带货可能，属商用场景，发布前必须确认许可；不确定时优先「AI 辅助画面占比低 + 明确声明」。
2. **AI 声明**：第 03 期 P0 教训——片尾要有**画面 + 旁白双重声明**；用了生成画面后措辞升级为「部分画面由 AI 生成」。
3. **模型合规**：应用内置大量社区微调（含 NSFW、换脸），**不要用换脸/去衣类工作流**；正式产出只用官方 FL2VA/Ref2VA 与已核实来源的加速 LoRA。
4. **数据安全**：租用实例停机 3 天后释放，**不要上传未发布稿件、真实姓名、联系方式**；提示词也不夹带个人信息。
5. **稳定性**：cookie 7 天有效但实例停机即失效；长任务写成「提交 → 轮询 → 下载」的可重试脚本。

## 七、复现清单

```
comfyui-h3-5090/
├── README.md                 # 本文
├── prompts.md                # 第 04 期分镜提示词库（S1–S5 + 负向清单）
├── tools/comfy_client.py     # 门禁登录 + ComfyUI API 客户端（stats/nodes/models/run/history）
├── tools/upscale_video.py    # 768p → 1080p 帧级超分（LoadVideo→4x-UltraSharp→lanczos→带音轨重封装）
└── workflows/t2v_api.json    # 实测用的 23 节点 API 工作流（可直接 /prompt 提交）
```

复现步骤：

```bash
export H3_USER=... H3_PASS=...
python3 tools/comfy_client.py stats
python3 tools/comfy_client.py run workflows/t2v_api.json --out out/ \
  --set '140:131.prompt=<你的提示词>' --set '140:131.width=1280'
python3 tools/upscale_video.py out/MiniMax_H3_00001_.mp4 --out out/ --width 1920 --height 1080
```

出片后处理（与现有管线对齐）：

```bash
# 768p → 1080p + 统一影调（teal-orange、暗角、颗粒）
ffmpeg -i in.mp4 -vf "\
scale=1920:1080:flags=lanczos,eq=contrast=1.08:saturation=1.12:gamma=0.98,\
vignette=PI/4.6,noise=alls=7:allf=t+u" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p -r 24 -c:a aac -b:a 192k out.mp4
```

> 生成物自带音轨，`-c:a aac` 会重编码保留；只用画面时加 `-an`，音效另配。测试片与抽帧按仓库惯例不入库，需要时按上面步骤重新生成。

## 八、结论：对 v工程 agent-workspace 的增益判断

**增益是实的，但只在「画面质感」这一层，不在「结构」这一层。**

- **能提升的**：实拍质感镜头从「Pexels 里碰运气」变成「按分镜定制」；H3 原生音轨还能补环境声；单条 ¥0.09、2 分钟出片，试错成本比改一次渲染器低两个数量级。
- **还能顺带缓解第 03 期评审的 P1**：研究段的信息卡感，可以靠插入 1–2 个真实感镜头打断长镜头节奏。
- **不能替的**：三条曲线的数学精确性、1080p 以上分辨率、时间轴与字幕节奏，以及选题/核实/判断。
- **建议下一步**：用 `prompts.md` 的提示词各出 2 个 seed，与现有 Pexels 素材做 A/B，按《优化意见》§6 的「静音观看 + 闭眼听音」两轮验收，再决定是否进第 04 期正片。
