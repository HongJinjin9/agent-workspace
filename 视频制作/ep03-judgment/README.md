规格：9:16 1080×1920 / 24fps / **3:53.78（233.779s）**；不出镜、不署名、无职业信息；画面/配音含 AI 辅助制作并在片尾声明。

## 一、相对前两期做了什么（按优化意见逐条落实）

| 优化意见 | 本期做法 |
| --- | --- |
| 动画：运动要回答「为什么现在动」 | 每个显著运动都绑定叙事：答案纸**从屏幕滑出**落到桌面（生成）、答案纸**盖住手写初判**（跳过初判）、初判纸**掀开露出空白判断框**（判断被欠下）、**账页落笔**写「记到我自己名下」、三问**笔尖逐条写下**、答案纸**翻面成反例**。没有匀速推拉与常驻光带。 |
| 视觉层级：一屏一个第一视觉重点 | 全片无进度条、无章节卡常驻、无闪白转场、无逐镜 whoosh；字幕字号降到 42、不加底条，作为辅助层；纸面文字承担信息，屏幕花字只在少数段落（片名、S3「相关不是证明」、S4 段首、S6 标题与结尾卡）出现，且不与纸面大字同屏争抢。 |
| 每期重做少量英雄镜头 | 5 个英雄镜头用自研 3D 桌面/纸张/印章渲染：①答案纸从屏幕飞落到桌面 ②答案盖住初判 ③掀纸露出「判断？」与朱印「欠」 ④翻面「答案→反例」 ⑤三问落笔。其余氛围镜头用 Pexels B-roll 压暗+调色，普通镜头不堆效果。 |
| 配音：保留音色身份、恢复表演层次 | 仍用 `zh-CN-YunjianNeural`，但改为**逐句 TTS + 逐句表演参数**（rate −14%…+3%、pitch −3Hz…+1Hz），关键句前后插入真实留白（S1 末 1.76s、三问各 0.88/0.88/1.08s、标题句前近静音）；句间 8–15ms 收发淡化 + 短房间混响粘合；80Hz 低切/轻去齿音/轻压缩，不做广播腔。 |
| 配乐：每期专属声音记忆点 + 情绪曲线 | **原创合成配乐（numpy，无外部曲库）**：D 小调「账页/滴答 + 稀疏钢琴」主题动机 → S5 转 F 大调 → S6 收束；按段调度而非全片铺满，S1 末与标题句前人工停乐/退开；sidechain 只做保底（最大 −3dB）。不复用第 01/02 期任何曲目。 |
| 音效只在语义发生作用时出现 | 全片仅 8 处：落印 1 次、书写 1 次、impact 3 次（欠了判断力 / 判断力债务 / 最贵的不是算力）、whoosh 1 次（S1→S2 空间转换）、纸张滑动 1 次、第三问前 riser 1 次。 |
| 先做短样再推全片 | 先单独渲染 S1（0:04–0:23）与 S6 三问（2:55–3:13）两段样片，检查静音观看可读性、一屏一重点、留白与音乐退让，通过后再全片渲染。 |

## 三、声音实测

- 旁白：50 句逐句 edge-tts（`zh-CN-YunjianNeural`），逐句表演参数见 `narration/performance.json`；句间显式留白合计 29.48s；测得有声段 RMS −14.8 dBFS。
- 成片音轨：`work/audio.m4a`，AAC 192k / 48kHz / 立体声；解码时长 233.771s（时间轴 233.779s，差 −8.6ms）。
- 母带：**I = −14.25 LUFS / TP = −1.75 dBTP / LRA = 3.70 LU**（两遍 loudnorm；无削波）。
- 旁白完整性硬校验：`audio.m4a` 与 `narration.wav` 在 S1/S3/S6 有声样点的相关系数 0.939 / 0.949 / 0.958；S1 末留白 RMS −60.2 dBFS（真静默）。独立 ASR 复核：whisper 对成片 0:08–0:22 的转写与逐字稿一致（「句子很顺…可过了一会儿，真让你解释为什么选它…你是欠了判断力」），确认旁白可听且内容完整。
- 详细逐句时长、配乐/音效调度、静默实测见 `work/audio-report.md`。

## 四、流水线

| 文件 | 作用 |
| --- | --- |
| `narration/performance.json` | 逐句表演谱：文本 + rate/pitch + 句后留白（权威输入，文字与稿件 §4 一致） |
| `tts_perf.py` | 逐句 edge-tts + 实测时长 + 拼接旁白 + `work/timeline_audio.json` + 句级 SRT |
| `music.py` | 本期原创配乐合成（numpy：账页滴答 + 钢琴 + pad/弦乐，D 小调→F 大调） |
| `sfx.py` | 音效合成（钢笔/纸张/印章/impact/whoosh/riser） |
| `build_audio.py` | 旁白处理 + 分段音乐床调度 + 音效 + sidechain + 两遍 loudnorm + 自检报告 |
| `fetch_assets.py` | Pexels B-roll 下载 + 抽帧成 2160×3840 竖屏背景底片 + manifest（见 `assets/manifest.json`） |
| `gen_textures.py` | 纸张/木桌/叠纸/朱印/圆形印章纹理（程序化） |
| `build_timeline.py` + `shots.json` | 以句级锚点生成 `work/timeline.json`（实测时间轴 + 36 镜） |
| `engine3d.py` | 透视相机 / 纹理四边形 / 3D 文字（自研轻量引擎） |
| `scene_judgment.py` | 渲染器：3D 桌面光栅化、纸张/印章/笔尖、数据动效、字幕、调色颗粒 |
| `gen_cover.py` | 封面（9:16 1080×1920 / 3:4 1200×1600） |
| `finalize.py` | 等帧 → 1080×1920 H.264 + AAC 编码 → 静帧/封面 → 自检 |
| `run_render.sh` | 分块渲染入口（`./run_render.sh <start_frame> <end_frame>`）；多段可同时起，实际并发由下文的渲染槽位限制 |

> **资源约束（本机 6 GB cgroup）**：2026-11-10 的 OOM 事故与 8 段并行渲染有关，脚本因此内置两道闸门：
> - 渲染：`scene_judgment.py` 用 `/tmp/ep03-render-slots` 下的文件锁限制同时渲染的进程数，默认 **2**；
>   环境变量 `EP03_RENDER_JOBS` 可覆盖（设为 1 即完全串行）。即使一次起 8 段，多出来的也会等待空槽。
> - ffmpeg：`fetch_assets.py` 的抽帧分析默认 **2** 并发（`EP03_FFMPEG_JOBS`）；`finalize.py` 编码加
>   `-threads 2`（`EP03_FFMPEG_THREADS`）。

复现（本机 `/app/vedio/ep03-judgment`）：

```bash
python3 tts_perf.py && python3 fetch_assets.py && python3 gen_textures.py
python3 music.py && python3 sfx.py && python3 build_audio.py
python3 build_timeline.py
# 并发：scene_judgment 自带渲染槽位（默认 2，EP03_RENDER_JOBS 可覆盖），一次起 8 段也只会同时跑 2 段。
mkdir -p work/frames
for r in "0 700" "700 1400" "1400 2100" "2100 2800" "2800 3500" "3500 4200" "4200 4900" "4900 5611"; do
  setsid nohup ./run_render.sh $r & done
python3 finalize.py
python3 gen_cover.py
# 规格/解码/响度/抽帧验证（交付工具不入库）：
#   ffmpeg -v error -i out/ep03-judgment.mp4 -f null -      # 全片解码无错误
#   ffmpeg -i out/ep03-judgment.mp4 -af loudnorm=print_format=json -f null -
```
