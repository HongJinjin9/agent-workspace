## 1. 立意与创作说明

### 1.1 一句话

**不是某家公司有病，是"变大"这件事本身带着病；差别只在于，谁承认它，谁假装看不见。**

### 1.2 为什么是这个题目

- **每个人都在里面待过，但很少有人讲清楚过**：一个决定过五个部门、签七个字，等批下来已经没人记得当初为什么要做。几乎所有人都经历过，但大多只能归结为"这公司不行"或"领导不行"。
- **它不是情绪，是数学**：协调成本随关系数增长，这是组合数学，不是管理风格问题。讲清了这层，就从"吐槽"升格为"看清"。
- **它接得住前四期**：第 01 期管精力，第 02 期管信息之真，第 03 期管判断之真，第 04 期管体感之真——这一期落到**组织之真**：我们每天身处的那个庞然大物，是怎么运行的。
- **它有一层反常识**：大家以为"职责不清"是管理没做好，其实往往是每个部门都管理得太"好"了。

### 1.3 与常见职场内容的差异

| 常见角度 | 本稿角度 |
| --- | --- |
| "这公司太卷了""领导不行"——情绪发泄 | 不讲具体公司，只讲规模自带的数学与结构 |
| "大公司病：流程长、效率低"——现象罗列 | 拆开机制：为什么加层反而更慢，闭环在哪 |
| "要扁平化、要授权"——口号式建议 | 给出可对照的公开案例（佐丹奴 vs Zara），只讲路径差异 |
| "员工要有变革心态"——要求个体 | 反过来：变革疲劳是组织管理不当的症状，不是员工不够坚强 |

### 1.5 可截取金句

1. 下属人数按加法涨，关系数按乘法涨。
2. 这不是哪家公司的毛病，这是所有大组织的出厂设置。
3. 官僚系统更擅长防止错误，而不是创造价值。
4. 复杂，就加层；加了层，更复杂；更复杂，再加层。
5. 职责不清，往往是因为每个部门都管理得太"好了"。
6. 员工不是不愿变革，是不觉得自己被装备好、被支持、被看见。
7. 每加一层，你都离那个最初想解决的问题，远了一点。

## 2. 视听设定

### 2.1 一句话视觉概念

**一张网在生长，越织越密，最后把自己缠住。**

### 2.2 影调 / 色彩 / 质感（承接 vibe 五层）

| 层 | 做法 |
| --- | --- |
| 运动 | 静帧用 `zoompan` 缓动推近（约 1.0→1.12）+ 约 6% 横向漂移；静帧叠柔和移动光条 |
| 色彩 | `eq=contrast=1.08:saturation=1.12:gamma=0.98` |
| 质感 | 暗角 `vignette=PI/4.6` + 胶片颗粒 `noise=alls=7:allf=t+u` |
| 构图 | 2.35:1 遮幅，teal-orange 偏移 |
| 文字 | 动态排版（位移 + 缩放 + 淡入），克制使用 |
| **数据** | **第六层**：关系网、层级堆叠、齿轮互锁，均依附实拍或真实三维空间 |

**总原则**：前五层统一克制，第六层才站得住。第 03 期的教训就在这里——为了"干净"削掉前五层，电影感随之下降。

### 2.3 核心视觉母题：一张越织越密的网

| 段 | 视觉 | 为什么是它 |
| --- | --- | --- |
| S1 钩子 | 走廊里，一份文件被人一路递过去，每递一次盖一个章，盖章声越来越密 | 观众立刻看见"过五关" |
| S2 组合爆炸 | **节点与连线**：3 个点 → 10 个点 → 20 个点，线数暴涨；画面被线填满 | 关系数按乘法涨，看得见 |
| S3 防御性结构 | **一层层堆叠的楼板**：每加一层，电梯要多停一次，通道要绕一次；楼越高，下楼越慢 | 加层的副作用具象化 |
| S4 职责不清 | **许多小箭头**：每个箭头都指向"自保"，合起来中央形成一块空白——事情卡在缝里 | 理性自保的合力，可视 |
| S5 变革疲劳 | **一条被反复拉起的曲线**：一次次被拉高又落下，幅度一次比一次小，最后拉不动 | 变革疲劳的生理感 |
| S6 收束 | 网慢慢松开一条缝，光透进来；不是剪断，是留出通行的路 | 不是推倒，是疏通 |

### 2.4 三条数据的生成约束

> **曲线与网络必须由真实数学关系生成，不能手绘。**

- S2 关系网：节点数 n 对应的连接数按组合数 n(n−1)/2 生成，节点位置用布局算法，不用手摆；
- S3 层级堆叠：每加一层，路径长度按实际层数递增，电梯停靠次数同步增加；
- S5 变革曲线：每次"变革"抬升幅度递减，模拟疲劳累积；
- 手绘会露馅——网看起来"假密"，观众一眼能察觉节奏不对。

### 2.5 三个视觉层次

| 层次 | 内容 | 作用 |
| --- | --- | --- |
| **空间层** | 实拍：写字楼走廊、会议室、工位、电梯、文件流转 | 建立"我在其中" |
| **结构层** | 网络、层级、箭头、曲线 | 建立"看懂了" |
| **人层** | 手部特写、递文件的手、盖下印章的瞬间 | 建立"这就是我" |

三层交替，结构层压在实拍之上，有景深归属，不做独立图表卡。

### 2.6 镜头语言与节奏

- 主镜头：35mm 环境 + 85mm 物件 + 100mm 微距（印章、文件边缘、电梯按钮）。
- 运动克制：缓推、轻微手持、焦点转移；网络与曲线用"生长"而非"弹出"。
- 每 8–12 秒一个视觉变化。
- **不使用**：进度条、常驻章节卡、闪白转场、逐镜 whoosh——第 03 期已验证这些会削弱叙事。

### 2.7 声音设计

- **旁白**：男声，中慢速；S1 带一点苦笑，S2–S3 转为分析，S4 是全片最重的一锤（放慢），S5 压低，S6 收束不喊口号。
- **BGM**：段落性格分明——
  - S1：走廊脚步声 + 稀疏钢琴
  - S2：脉冲加密，随节点增多而变密
  - S3：低频下沉，机械感
  - S4：几乎抽空，只剩心跳
  - S5：弦乐反复拉起又落下
  - S6：回到主调，弦乐收束
- **音效**：全片不超过 8 处，只在语义节点（盖章声、电梯叮、网络连线声、关键句 impact）。
- 混音：口播高于 BGM 约 6dB；关键句前留白。响度守 -14 LUFS / TP ≤ -1 dBTP。

### 2.8 字幕与花字

- 主字幕：思源黑体 Bold，白字 + 60% 黑描边，横屏底部居中，单行 ≤18 字。
- 花字：全片 **4–5 处**，只在关键数字与概念（关系数、74%→43%、防御性结构、组织规模负效率）。
- **手机端可读性**：横屏 1080p 缩到约 390px 宽时，字号建议不小于 48px（第 03 期 42px 曾被指偏小）。

### 2.9 画幅与平台

- 主版：1920×1080 横屏，24fps，2.35:1 遮幅。
- 竖屏版：另出 9:16，重排而非直接裁切。
- 平台短标题不使用中文逗号。

### 2.10 匿名与不出镜

- 全片无人物正脸，以手部、文件、走廊、电梯为主。
- **不出现任何具体公司名、标识、工牌、制服**。
- **片尾必须显示「本片画面与配音含 AI 辅助制作」**——第 03 期 P0 教训。

## 4. 逐字稿

> 括号内为口播提示，**不读、不送 TTS**。

### S1｜钩子 0:00–0:25

（语气：像在讲一件大家都懂的事，带一点苦笑；「没人记得」处轻停）

你有没有在那种公司待过。

一个决定，走五个部门，签七个字。

等批下来，当初为什么要做这件事，已经没人记得了。

我以前以为，这是管理没做好。

后来发现，不是。

这是「大」本身带的病。

### S2｜组合爆炸 0:25–1:05

（语气：转入分析，「加法的速度」「乘法的速度」对比要清楚）

法国有个数学家叫格雷卡纳斯，他算过一笔账。

一个人管三个下属，要考虑的关系是几对。

管十个人，是几十对。

管二十个人，是几百对。

下属人数按加法的速度涨，关系数按乘法的速度涨。

这就是为什么，人一多，沟通就开始漏。

周雪光在讲中国官僚体制的时候，给它起了个名字，叫「组织规模负效率」——

随着组织扩大、等级链条延长，信息分布就越散，不对称就越严重，效率就往下走。

这不是哪家公司的毛病。

这是所有大组织的出厂设置。

### S3｜防御性结构 1:05–1:55

（语气：笃定，讲机制；「防御性结构」四字放慢；最后三句是闭环，一句一顿）

那为什么有些公司活得挺好？

差别在，它怎么对付这种复杂。

最省事的办法是加一层。

但加层有个副作用。

詹姆斯·威尔逊研究官僚组织，说过一句话：

官僚系统的本质，是一种「防御性结构」——它更擅长防止错误，而不是创造价值。

加一层，就多一道审批；

多一道审批，就多一个「这事不归我管」。

唐斯说得更直接：监控者把越来越复杂的规则压给执行部门，执行部门灵活办事的能力就下降了。

于是成了一个圈：

复杂，就加层；

加了层，更复杂；

更复杂，再加层。

### S4｜职责不清的真相 1:55–2:35

（语气：全片最重的一锤，放慢；「太『好』了」要咬住）

所以很多公司里那个「职责不清」，是怎么来的？

大家通常觉得，是管理没做好。

我看恰恰相反。

职责不清，往往是因为每个部门都管理得太「好」了。

每个人都理性地自保，少做少错，不做不错。

每个环节都在避免「多做多错」。

合起来，就是谁都不越界，谁都不担责，事情卡在缝里。

这不是谁偷懒。

这是所有人的理性，加在一起，变成了整体的不理性。

### S5｜变革疲劳 2:35–3:10

（语气：压低，像说一件不太愿意承认的事；最后一句放轻）

还有一个更隐蔽的代价。

流程老在变，人就不信了。

管理学里有个词，叫变革疲劳。

有研究发现，反复重组会直接导致变革疲劳，然后员工就开始抵抗下一次变革。

Gartner 有个数字：

员工支持企业变革的意愿，2016 年是 74%，2022 年跌到 43%。

Gallup 的调查说，73% 的员工表示，公司过去一年经历过破坏性变革。

Prosci 给了个很准的定义：

变革疲劳，发生在一个人或团队，至少超过了他们承受能力一个变革项目的时候。

戴尔·卡内基有一句话说得很实：

员工不是不愿变革，是因为他们不觉得自己被装备好、被支持、被看见。

### S6｜收束 3:10–3:45

（语气：先稳后轻，不喊口号；最后一句放慢）

那怎么办？

我不打算给出成功学的三条。

只说三个我信的方向。

第一，承认「大」本身有代价。

不要假装可以通过管理把它消灭。

承认它，才会防它。

第二，少加层，多加桥。

佐丹奴当年决策链条太长，反应慢；Zara 扁平化，供应链快，就活下来了。

区别不在谁更聪明，在谁的路径更短。

第三，变革要有节奏。

不是越多越好。

一个组织能承受的变革是有上限的，超过了，最好的方案也会被执行成最坏的结果。

说到底，公司变大不是错。

错的是把「加层」当成唯一的解药。

因为每加一层，你都离那个最初想解决的问题，远了一点。

| 美特斯邦威 | 过度追求门店扩张和销售数字，忽视品牌升级与设计创新；快时尚崛起时未能坚持品牌定位，频繁调整风格与渠道 | 同上 |

> **使用边界**：以上案例仅用于说明「同一类问题，不同应对方式导致不同结果」，**不用于论证任何特定公司存在问题**。片中不出现任何具体公司名。

### 5.3 C 级：本稿的通俗概括（非学术定义）

- **「下属人数按加法涨，关系数按乘法涨」**：对格雷卡纳斯公式的通俗表述，非严格数学陈述。
- **「复杂 → 加层 → 更复杂 → 再加层」**：对科层膨胀循环的简化表达，实际组织演化远比此复杂。
- **「职责不清，是因为每个部门都管理得太『好』了」**：本稿的核心反常识判断，属于分析视角，非管理学定论。
- **「每加一层，你都离那个最初想解决的问题远了一点」**：修辞性概括，非可量化结论。

### 5.4 D 级：不写死的数字

- 具体的「管理幅度上限人数」——学界无统一定论，古典理论认为高层 4–8 人、基层可达 30 人，因行业与任务性质差异极大，片中不列举。
- 具体企业的变革频次或层级数量——不掌握公开数据，片中不涉及。
- 「变革疲劳导致多少损失」——现有研究多为定性或特定样本，不做普遍化定量断言。

## 7. 制作交接建议

### 7.1 分镜接口

`segment_id｜本段回应的问题｜信息增量｜视觉第一重点｜运动表达的变化｜旁白语气｜音乐任务｜音效任务｜验收问题`

### 7.2 优先试片段落

- **试片 A：S2 组合爆炸**——检验关系网能否让观众直观感受到「乘法」而非「加法」；
- **试片 B：S4 职责不清**——检验「理性自保的合力」这个反常识判断能否不用文字卡讲清。

### 7.3 动画方向建议

- **网络要「生长」，不要「弹出」**：节点一个个加上去，线一根根连起来，让观众看见密度在涨。
- **层级要「升高」，不要「堆卡片」**：观众应该感受到「楼越盖越高，下楼越来越慢」。
- **箭头群要有「离心感」**：所有箭头都朝外，中间那块空白就是「事情卡住的地方」。
- **避免**：进度条、常驻章节卡、闪白转场、逐镜 whoosh。

### 7.4 成本提示

关系网络、层级堆叠、箭头群、变革曲线四组都是程序化生成，渲染量中等。相比第 04 期的三层结构，本期数据层更轻（无物理仿真），但**数学精度要求更高**——曲线形状必须与公式吻合一，否则内行一眼看出假。
